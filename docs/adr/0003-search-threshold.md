# ADR-0003: Порог векторного поиска

Статус: принято.

## Контекст

Используется google/embeddinggemma-300m на CPU.
Размерность векторов — 768, векторы нормализованы.

Префикс вопроса:
`task: search result | query: ...`

Префикс документа:
`title: раздел или none | text: ...`

Для выбора порога собраны 12 вопросов по документам
с заранее выбранными нужными чанками и 5 вопросов не по теме.

Замеры выполнены в векторном режиме без отсечения результатов
и без дополнительного приоритета кодов программ.

Полный отчёт: ../evaluation/search-calibration.json.

На калибровочном наборе нужный чанк находится:
- на первом месте для 11 из 12 вопросов;
- в первых пяти результатах для всех 12 вопросов.

## Решение

Установить SEARCH_SIMILARITY_THRESHOLD=0.30.

Значение 0.30 выбрано как удобное округлённое число внутри
наблюдаемого промежутка. Порог 0.31 даёт тот же результат
на калибровочном наборе. Оптимальность конкретного значения
не установлена.

Порог находится внутри наблюдаемого промежутка между
максимальной похожестью посторонних вопросов (0.171631)
и минимальной похожестью нужных чанков (0.474197).

По измеренным значениям он сохраняет все 12 нужных чанков
и отсекает все результаты для пяти посторонних вопросов.

Порог применяется к cosine similarity только в векторной ветке.
Полнотекстовая ветка гибридного поиска работает независимо от него.
Баллы RRF для выбора порога не используются.

## Ограничения

Набор небольшой и использован для выбора порога.
Результаты не являются оценкой качества на независимом наборе.

Нужный чанк о сроке рассмотрения заявления занимает пятое место.
Изменение порога не исправляет эту ошибку ранжирования.

При смене модели, префиксов, нарезки или состава документов
замеры необходимо повторить.
